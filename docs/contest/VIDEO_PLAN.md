# Physical demonstration plan

Target length: about 90 seconds. Capture when the device is available.
This is a shot plan, not a record of a completed demonstration.

| Time | Shot | Suggested narration |
|---|---|---|
| 0–15 s | Stable front view of the real screen | “Today's Adventure turns weather and time into a small invitation to enjoy the day.” |
| 15–30 s | Close-up of headline, wonder and local outing | “The measurements are context. The result is a sentence and a few suggestions.” |
| 30–45 s | Signal-flow graphic | “Wi-Fi brings in weather data. Local rules select the message and compose one e-ink frame.” |
| 45–65 s | Uncut scheduled refresh, recorded near the hour | “The device wakes, updates the display and returns to sleep.” |
| 65–85 s | Side-wheel press and facts card | “The facts remain available when you want them.” |
| 85–95 s | Main screen returning; label elapsed time if cut | “After about a minute it returns to the everyday view.” |

Keep the refresh segment uncut. For the one-minute facts-card dwell, either
show it in full or label any time skip. Do not speed up footage without labeling
it. Keep a visible clock or a continuous recording for any timing claim.

## Additional stills

- Full device, evenly lit, with the current screen sharp and no glare.
- A physical night-watch frame with the date/time context recorded.
- A physical facts card.
- An immediate-post-refresh and just-before-next-wake pair for retention evidence.
- Optional charging splash, labeled as charging mode rather than the main experience.

## Before recording

Check the current screen and power mode. Avoid accidentally recording Wi-Fi
credentials in terminals. No firmware changes are required to tell the contest
story. Do not make an OTA update part of the filmed demonstration unless its
release and recovery plan have already been validated.

## File naming and captions

Use names such as `device-night-2026-09-XX.jpg` and
`scheduled-refresh-2026-09-XX.mp4`, replacing XX with the actual day.
Caption each with the observed mode and capture date. Keep generated scene
art and ASCII examples labeled separately from physical photographs.
